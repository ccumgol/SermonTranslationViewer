## 1. 프로젝트 개요

**한국어 설교 음성을 실시간으로 여러 언어 자막으로 번역해 프로젝터·OBS·교인 폰에 송출하는 시스템.**

- 스택: Python 3 / FastAPI + WebSocket / (온라인) Gemini Live Translate / (오프라인) Qwen3-ASR + TranslateGemma(Ollama)
- 규모: 서버 코드 약 1,977줄(12개 모듈), 웹 프런트 약 1,050줄(4개 화면), 단위 테스트 20개
- 핵심 철학: *"실시간 AI 번역 하나에 모든 신뢰를 걸지 않는다"* — 원고 교정·용어집·온오프라인 이중화

화면 4종: 송출(`/`) · 운영자(`/operator`) · 모바일(`/m`) · QR 큰화면(`/qr-view`).

## 2. 아키텍처 평가

```
[믹서/마이크] → 오디오 캡처(16kHz mono) → fan-out(복제)
                                            │
                  ┌─────────────────────────┴──────────────────────┐
             [온라인 GeminiBackend]                        [오프라인 LocalBackend]
        언어마다 Gemini Live 세션               공유 STT 1회 → 언어별 MT N회
                  └─────────────────────────┬──────────────────────┘
                              자막 안정화 + 원고/용어집 교정
                                            ▼
                        WebSocket 브로드캐스트(FastAPI) → 4개 화면
```

**강점**
- **백엔드 추상화**(`TranslationBackend`/`TranslationSession` 프로토콜)로 온·오프라인이 오디오·자막·UI를 공유하고 런타임 전환 가능 — 확장성·유지보수성의 핵심 장점.
- **오디오 fan-out** 설계로 "1 오디오 → N 언어 세션"을 깔끔히 해결.
- **관심사 분리**: 순수 로직(`subtitle_engine`, `glossary`, `sermon_script`, `languages`)이 I/O에서 분리되어 테스트 가능.
- **불변 설정 객체**(`@dataclass(frozen=True) Settings`)로 설정 변조 방지.
- **재구성 동시성 제어**: `reconfig_lock` 으로 언어/백엔드/장치 재구성 경합(유령 워커) 차단.

**구조적 리스크**
- `ws_server.py` 가 689줄로, 라우팅·상태·워커 오케스트레이션·명령 처리·인증을 모두 담당(전역 CLAUDE.md 기준 800줄 상한 근접). → 인증/명령 처리를 별도 모듈로 분리 권장.
- preview SDK 필드명 의존(`live_session.py`) — 모델·SDK 변경 시 취약(handover에도 명시).

## 6. 보안 분석 및 개선 제안 ★핵심

> `security-reviewer` 정밀 분석 + 코드 직접 검토 결과. 의존성 CVE 스캔(`pip-audit`)은 이상 없음.
> **"신뢰된 LAN" 전제를 감안한 현실적 평가**이나, 아래 CRITICAL 2건은 그 전제 자체를 무너뜨립니다.

### 🔴 CRITICAL

#### C-1. WebSocket Origin 미검증 → CSWSH(교차 사이트 웹소켓 하이재킹)
- 위치: [ws_server.py:635-682](../server/ws_server.py:635) — `/ws` 핸들러가 `Origin` 헤더를 전혀 검사하지 않고 `ws.accept()`.
- 위험: WebSocket 핸드셰이크는 브라우저 동일출처정책(SOP) 대상이 **아니므로**, **아무 외부 웹사이트**나 JS로 `new WebSocket("ws://<교회-LAN-IP>:8000/ws")` 를 열 수 있음. 운영자 PC가 교회 LAN에 연결된 채 무관한 웹페이지(광고·피싱)를 열기만 해도, 그 페이지가 배경에서 서버에 연결·명령 전송 가능.
- 영향: 토큰 미설정 시(기본 상태) **모든 운영 명령**(방송 종료, 언어/백엔드 변경으로 비용 유발 등) 원격 실행. 토큰 설정 시에도 **읽기(실시간 전사·번역·장치명) 도청**은 가능.
- 권장: `ws.accept()` 이전에 `Origin` 헤더를 화이트리스트(자기 호스트/LAN IP)와 비교, 불일치 시 `4403` close. **구현 비용 낮고 효과 큼 — 최우선.**

#### C-2. OPERATOR_TOKEN 기본 부재 + 강제 안 됨 → 기본 설정이면 인증이 사실상 없음
- 위치: [config.py:73](../server/config.py:73) · [ws_server.py:430-435](../server/ws_server.py:430)(경고만) · [ws_server.py:669-670](../server/ws_server.py:669)(`if token and ...` — 토큰 빈 값이면 검사 통째 스킵)
- 위험: `.env.example` 기본이 `WS_HOST=0.0.0.0` + 토큰 공란. 배포자가 토큰을 안 채우면 **게스트 Wi-Fi 포함 같은 LAN 누구나** `/operator` 로 방송 종료·원고 조작 등 가능.
- 권장: `WS_HOST=0.0.0.0` + 토큰 공란이면 **기동 거부(fail-fast)** 하거나, `secrets.token_urlsafe(24)` 로 **임시 토큰 자동 생성 후 콘솔 1회 출력**. "토큰 없음"을 기본값으로 두지 말 것.

### 🟠 HIGH

| ID | 이슈 | 위치 | 권장 |
|---|---|---|---|
| **H-1** | 토큰 비교 비-상수시간 + **브루트포스 무제한**(같은 WS에서 초당 수천 회 시도 가능) | [ws_server.py:670](../server/ws_server.py:670) | `hmac.compare_digest` + 인증 실패 카운트→연결종료/백오프 |
| **H-2** | 토큰이 **URL 쿼리(`?token=`)** + **평문 `ws://`** 전송 → 히스토리·패킷 스니핑 노출 | [operator/index.html:300-303](../web/operator/index.html:300) | 실사용 시 HTTPS/WSS(mkcert 등) 안내, 토큰은 `sessionStorage` prompt 입력 고려 |
| **H-3** | Rate limiting 전무 → `set_backend`/`set_languages` 연타로 세션 재시작 스톰 + Gemini 과금 급증 | [ws_server.py:563-601](../server/ws_server.py:563) | 운영 명령에 2~3초 쿨다운/토큰버킷 |
| **H-4** | WS 메시지 크기·연결 수 상한 미명시(`set_script`/`set_style` 길이 무제한) | [ws_server.py:661-663](../server/ws_server.py:661) | `uvicorn(ws_max_size=…)`, 원고 길이 상한, `Hub` 최대 연결 수 |

### 🟡 MEDIUM

- **M-1** 인증 없는 `init` 브로드캐스트에 장치명·백엔드·용어 개수 등 내부정보 노출([ws_server.py:640-660](../server/ws_server.py:640)) → 운영자 전용 필드는 인증 후 전송.
- **M-2** `set_style` 이 임의 키를 상태에 병합, `color` 길이 무제한([ws_server.py:572-576](../server/ws_server.py:572)) → Pydantic 화이트리스트 검증.
- **M-3** `/qr.svg?text=` 길이·횟수 무제한·무인증 → 임의 QR 생성 오픈프록시·DoS 소지([ws_server.py:538-547](../server/ws_server.py:538)) → 길이 상한 + rate limit.

### 🟢 LOW

## 7. 사용자 편의성 분석 및 개선 제안 ★핵심

전반적으로 **비개발자 봉사자 배려가 뛰어남**(운영자 대시보드에서 예배 중 모든 조작, QR/PWA, 자동 브라우저). 아래는 그 위에서의 개선 제안.

### 7.1 운영/봉사자 관점

| 우선 | 제안 | 이유·근거 |
|---|---|---|
| 높음 | **토큰 입력 UX 개선** | 현재 토큰을 URL `?token=` 로 붙여야 함([operator/index.html:300](../web/operator/index.html:300)). 봉사자가 매번 긴 주소 입력은 실수 유발. → 최초 1회 입력 후 `sessionStorage` 저장, "토큰 포함 QR/북마크" 제공(보안 H-2와 함께 해결) |
| 높음 | **무발화 자동 방송 종료(옵션)** | 현재는 경고만([ws_server.py:405](../server/ws_server.py:405)). 끄는 걸 잊으면 온라인 비용 지속 누적. → `IDLE_STOP_MIN` 옵션으로 N분 무발화 시 자동 종료(기본 off, 예배 중 오종료 방지) |
| 중간 | **온보딩/첫 실행 가이드** | setup-guide 는 훌륭하나 텍스트 위주. → 운영자 화면에 최초 접속 시 3단계 미니 안내(장치 선택→언어→방송 시작) |
| 중간 | **오류 상황 사용자 피드백 일관화** | `backend_error`·`device_error`·`auth_error` 는 있으나(양호), 네트워크 끊김·재연결 상태 표시는 약함 → WS 연결 상태 배지 추가 |
| 낮음 | **프리셋 저장** | 자주 쓰는 언어·색·스타일 조합을 프리셋으로 저장/복원 |

### 7.2 교인(모바일) 관점

| 우선 | 제안 | 이유·근거 |
|---|---|---|
| 높음 | **언어 선택 유지** | 모바일에서 선택 언어를 `localStorage` 저장 → 재접속·새로고침 시 자동 복원(현재 매번 재선택 추정) |
| 중간 | **접근성(글꼴 크기·대비)** | 교인 폰에서 본문 글자 크기 조절·고대비 모드. 시니어 교인 배려 |
| 중간 | **연결 상태·지연 표시** | "실시간 연결됨/끊김" 표시로 폰 자막이 멈춘 건지 발화가 없는 건지 구분 |
| 낮음 | **원문 병기 옵션** | 학습·확인용으로 한국어 원문과 번역 동시 표시 토글 |

### 7.3 확장성 관점(문서에도 언급된 향후 과제)
- **i18n 로케일 분리**: 현재 UI 다국어는 한/영 사전 방식. 3개 이상이면 로케일 JSON 분리 권장.
- **로그 고도화**: JSONL → SQLite + 사후 검토 UI, 세션별 통계.
- **VAD 문장 재조합**: 강제 분할 조각을 문장 끝까지 모아 번역(정확도↑).

## 9. 우선순위별 실행 로드맵

**1단계 — 보안 하드닝 (즉시)**
1. C-1 WebSocket Origin 검증
2. C-2 토큰 자동생성 또는 기동 거부(fail-fast)
3. H-1 `hmac.compare_digest` + 인증 실패 rate limit

**2단계 — 견고성·편의성 (단기)**
4. H-3/H-4 명령 쿨다운, WS 크기·연결 상한, 원고/스타일 길이 검증(Pydantic)
5. 토큰 입력 UX(`sessionStorage`) + 무발화 자동 종료 옵션
6. 모바일 언어 선택 유지(`localStorage`)

**3단계 — 품질·확장 (중기)**
7. WS/인증 통합 테스트 추가, `ws_server.py` 모듈 분리
8. 보안 헤더 미들웨어, 의존성 락파일 + CI `pip-audit`
9. i18n 로케일 분리, 로그 SQLite화, VAD 문장 재조합

## 10. 결론

translateViewer 는 **명확한 도메인 이해와 뛰어난 문서화, 온·오프라인 이중화라는 견고한 설계**를 갖춘
완성도 높은 프로젝트입니다. 코드 구조와 정확도 설계, 비개발자 운영 배려는 특히 모범적입니다.

다만 **WebSocket 인증 경로에 구조적 취약점(C-1·C-2)** 이 있어, "신뢰된 LAN" 전제만으로는
방어되지 않는 실질적 위험이 존재합니다. 이는 **낮은 구현 비용으로 해결 가능**하므로 최우선 처리를 권장합니다.
보안 하드닝과 몇 가지 편의성 개선을 마치면, 실제 예배 환경에서 안심하고 운영할 수 있는 수준에 도달합니다.
